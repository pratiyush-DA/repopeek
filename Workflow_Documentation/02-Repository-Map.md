# Repository Map

This document provides a comprehensive structural inventory of the repository, identifying the architectural significance, symbols, dependencies, and operational roles of every directory and module.

---

## Top-Level Repository Structure

```text
repopeek/
├── repopeek/                   # Core Python application package
│   ├── bridges/                # Cross-language boundary bridges (HTTP client-server)
│   ├── context/                # Context compiler, constraint extractor, change planner
│   ├── daemon/                 # Incremental file watcher and background sync daemon
│   ├── discovery/              # File crawler, type classifier, hashing, ignore rules
│   ├── enrichment/             # 5-tier story cascade, cache, governor, and verifier
│   ├── evaluation/             # 4-level benchmarking framework, metrics, reporting
│   ├── graph/                  # Graph builder, symbol resolver, blast radius, lenses
│   ├── llm/                    # LLM provider abstractions, Groq adapter, fallback, mock
│   ├── models/                 # Canonical property graph schema (Pydantic models)
│   ├── parsers/                # Polyglot parsers (Python, TS/JS, SQL, Shell, Config)
│   ├── query/                  # Graph query engine, context packing, MCP JSON-RPC server
│   ├── retrieval/              # Hybrid retrieval, intent resolution, normalization, RRF
│   ├── storage/                # JSON sharding, SQLite CTE cache, Obsidian exporter
│   ├── temporal/               # Git commit history miner & co-change matrix
│   ├── viewer/                 # Local web force-directed graph viewer & HTTP server
│   ├── cli.py                  # Main CLI entry point and dispatch orchestrator
│   └── config.py               # Global configuration model (RepopeekConfig)
│
├── benchmarks/                 # Ground truth benchmark tasks for evaluation
│   └── v1/tasks.yaml           # 50 verified evaluation tasks across 7 categories
│
├── tests/                      # Pytest test suite (178 unit and integration tests)
│   ├── fixtures/sample_repo/   # Polyglot sample repository for testing
│   └── test_*.py               # 24 test suites covering all subsystems
│
├── docs/                       # Initial architectural requirements and schema specs
│   ├── ARCHITECTURE.md         # Early conceptual architecture sketch (MVP phase)
│   ├── graph_schema.json       # JSON schema definition for property graph
│   ├── MVP_REQUIREMENTS.md     # Phase 1 MVP requirements
│   └── TASKS.md                # Phase 1 development task breakdown
│
├── testing/                    # External validation testbeds
│   └── da-assistant/           # Real-world polyglot target repository (12 benchmark tasks)
│
├── my_obsidian_vault/          # Sample exported Obsidian vault generated by RepoPeek
├── output/                     # Default output directory for generated graph artifacts
├── pyproject.toml              # Package configuration, build backend, dependencies
└── requirements.txt            # Frozen dependency versions
```

### 2. `repopeek/models/` (Canonical Data Schema)

- **Purpose:** Single source of truth for the property graph data structures, typed relationships, spans, facts, and provenance.
- **Key Modules:**
  - [`schema.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/models/schema.py): Defines `Confidence`, `EdgeType`, `Span`, `NodeFacts`, `NodeStory`, `NodeProvenance`, `NodeCard`, `Evidence`, `Edge`, and `CanonicalGraph`.
- **Dependencies:** `pydantic` (`BaseModel`, `Field`, `model_validator`).
- **Dependents:** Used universally by all parsers, graph engines, storage adapters, and query tools.

### 3. `repopeek/discovery/` (Repository Scanner)

- **Purpose:** Deterministic filesystem crawler, ignore rule parsing, file type classification, and cryptographic content hashing.
- **Key Modules:**
  - [`crawler.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/discovery/crawler.py): `discover_repository()` walks filesystem in alphabetical order, skips binaries and files exceeding size caps.
  - [`classifier.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/discovery/classifier.py): `classify_file()`, `FileType`, `EXTENSION_MAP`, `SUPPORTED_TYPES`, `is_binary_file()`, `check_shebang()`.
  - [`hasher.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/discovery/hasher.py): `compute_file_hashes()`, `hash_content()`, `compute_git_blob_sha()`.
  - [`ignore.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/discovery/ignore.py): `IgnoreRuleSet`, `IgnoreRule` parsing `.repopeekignore`, `.gitignore`, and built-in ignore directories (`.git`, `node_modules`, `venv`, `__pycache__`, etc.).
- **Dependencies:** `pathlib`, `os`, `hashlib`, `fnmatch`.
- **Dependents:** `repopeek/graph/builder.py`, `repopeek/daemon/watcher.py`, `repopeek/cli.py`.

### 4. `repopeek/parsers/` (Polyglot Syntactic Extractors)

- **Purpose:** Extracts syntactic facts, declarations, dependencies, and data flows from source code into canonical `ParseResult` records.
- **Key Modules:**
  - [`base.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/parsers/base.py): Abstract base class `BaseParser` and `ParseResult` dataclass.
  - [`python.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/parsers/python.py): AST extraction for Python (classes, methods, functions, calls, imports, variables, def-use flows, embedded SQL via SQLGlot, syntax-error fallback parser).
  - [`typescript.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/parsers/typescript.py): Deterministic regex/lexical parser for TypeScript and JavaScript (classes, interfaces, type aliases, functions, arrow functions, methods, imports, exports, client HTTP calls).
  - [`sql.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/parsers/sql.py): SQL parser using `sqlglot` across Oracle, Postgres, and ANSI dialects (tables, queries, statements, table reads/writes).
  - [`shell.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/parsers/shell.py): Shell parser using `shlex` (commands, pipelines, executed script runs, environment variable assignments and reads).
  - [`config.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/parsers/config.py): JSON and YAML parsers flattening nested keypaths into atomic configuration cards.
- **Dependencies:** Standard library `ast`, `shlex`, `re`, `json`; third-party `sqlglot`, `yaml` (`pyyaml`).
- **Dependents:** `repopeek/graph/builder.py`.

### 5. `repopeek/graph/` (Graph Assembly, Resolution & Blast Radius)

- **Purpose:** Combines parse results, resolves cross-file references, computes mathematical blast radius, and generates specialized lenses.
- **Key Modules:**
  - [`builder.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/graph/builder.py): `GraphBuilder` coordinates parsers, resolves git provenance, invokes resolver and bridges, converts to NetworkX (`to_networkx()`), and performs single-file incremental updates (`update_file()`).
  - [`resolver.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/graph/resolver.py): `SymbolResolver` resolves cross-file imports, function/method calls, class inheritance, script targets, environment variables, configuration keys, and database tables.
  - [`blast_radius.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/graph/blast_radius.py): Multi-hop BFS engine calculating path confidence decay, combined multi-path confidence, distance decay, and partitioning into `direct`, `indirect`, and `excluded`.
  - [`lenses.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/graph/lenses.py): Projects 9 specialized views: `module`, `symbol`, `call`, `class`, `data`, `data_entity`, `config`, `process`, and `bridges`.
- **Dependencies:** `networkx`, `math`, `collections`, `repopeek/models/schema.py`.
- **Dependents:** `repopeek/query/engine.py`, `repopeek/context/compiler.py`, `repopeek/cli.py`.

### 6. `repopeek/bridges/` (Cross-Language Boundaries)

- **Purpose:** Connects client frontend API calls to backend route handlers across language boundaries.
- **Key Modules:**
  - [`http.py`](file:///c:/Users/pkumar2/OneDrive%20-%20Data%20Axle/Documents/AI_INIT/Repopeek/repopeek/bridges/http.py): `HttpBoundaryBridge`, `normalize_route_path()`, `paths_match()`, extracts route decorators (FastAPI, Flask, Express) and client calls (`fetch`, `axios`), producing cross-language `INVOKES` edges.

### 7. `repopeek/temporal/` (Git History Mining)
