# Conceptual Architecture

This document outlines the system architecture from repository ingestion to agent consumption. 

## High-Level Pipeline

```text
Repository
    ↓
File Discovery
    ↓
Language / File Classification
    ↓
Deterministic Parsing
    ├── Python → AST / functions / calls / imports
    ├── SQL → queries / tables / relationships
    └── JSON → configuration / referenced values
    ↓
Deterministic Graph
    ↓
Semantic Enrichment
    ↓
Semantic Overlay
    ↓
Unified Repository Graph
    ↓
Query / Agent Interface
```

## 1. Deterministic Layer (Substrate)
**Purpose:** Represents absolute facts derived mechanically from the source code.
**Rule:** Deterministic information must NEVER depend on an LLM if it can be extracted via static analysis. 
**Examples of Nodes:** `File`, `Function`, `SQLQuery`, `JSONConfig`, `Table`.
**Examples of Edges:** `CALLS`, `IMPORTS`, `READS`, `DEFINED_IN`.

## 2. Semantic Layer (Overlay)
**Purpose:** Represents higher-level business logic and meaning inferred from the deterministic structure.
**Rule:** An LLM contributes this layer, but every semantic node must be grounded in underlying deterministic nodes.
**Examples of Nodes:** `BusinessProcess`, `Story`, `BusinessConcept`.
**Examples of Edges:** `IMPLEMENTS`.

## 3. Code → Story Pipeline
Semantic understanding is built bottom-up to prevent hallucination:
1. **Code Element:** Raw code is parsed.
2. **Function-Level:** LLM generates a summary for a specific function based on its AST.
3. **Module-Level:** LLM summarizes how connected functions interact.
4. **Business Process:** LLM groups module interactions into a unified "Story".

## 4. Provenance
Semantic information must be traceable to its source code. Semantic nodes must retain:
- Source file path
- Line ranges
- Connected deterministic code node IDs
- Confidence score (generated by LLM)
- Commit/Version (Implementation specifics: **TBD**)

## 5. Agent Use Case (Future Vision)
The graph enables an AI coding agent to perform safe impact analysis.
* **Agent Intent:** "Modify promotion email logic."
* **Graph Traversal:** Finds the `BusinessProcess` -> identifies `IMPLEMENTS` functions -> traverses `CALLS` and `READS` -> returns exact dependencies and callers.
* **Agent Action:** Agent safely edits only the required code with full business context.

## 6. Important Architectural Principle
**The graph is NOT intended to replace source code.** Source code remains the authoritative implementation. The graph is strictly an intelligence/index layer over the repository.
