# Provenance Engine

#architecture #provenance #auditability #traceability

## Overview
The Provenance Engine guarantees auditability and prevents hallucinated business logic from contaminating repository intelligence. It maintains bidirectional pointers between the [[Semantic_Overlay]] and [[Deterministic_Substrate]].

## Provenance Metadata Contract
Every semantic node generated by an LLM must capture:
- `source_filepath`: Relative path to physical file.
- `line_range`: Inclusive `[start_line, end_line]`.
- `target_node_ids`: Identifiers of linked deterministic nodes (e.g., `function:py1.process_employees`).
- `confidence`: Normalized float `[0.0, 1.0]` representing model certainty.
- `provenance_commit`: Git commit hash or version identifier (TBD in MVP).

## Traversal Verification
Agents traversing from a business query can trace downstream to the exact physical code lines:
`BusinessProcess` → `IMPLEMENTS` → `Function` → `DEFINED_IN` → `File` (lines X to Y).
